# テスト仕様書

## 1. テスト方針

本仕様書は、発表時に説明できる代表的な受入観点を、テストIDと証跡単位で整理したものである。合否はコード・自動テスト・ローカルE2Eで確認できる範囲に限定し、本番デプロイ、リモートD1、実PDFプリンタ、実運用バックアップの結果は未確認とする。

## 2. 環境・実行コマンド

| 項目 | 内容 |
|---|---|
| アプリ | Bun workspace、Vite React SPA、Hono Cloudflare Worker、Drizzle/D1 |
| ローカルURL | `http://localhost:5173`（既定） |
| データ | ローカルD1。テスト用seedを使用し、本番データは使用しない |
| 単体・統合 | `bun run test` |
| 型検査 | `bun run typecheck` |
| ビルド | `bun run build` |
| D1マイグレーション | `bun run db:migrate` |
| Workers設定確認 | `bun run deploy:dry-run` |
| E2E | `bun run e2e:test` または `bunx playwright test e2e/grade-management.spec.ts` |

## 4. 合格基準

- APIが許可されないロール・状態・確定状態を拒否する。
- 正常系の登録・保存・確定・出力・年度更新が、画面表示とDB結果の両方で一致する。
- 不正入力は日本語の修正可能なエラーを返し、内部情報・秘密値を表示しない。
- 取込・年度更新・出力の確認と反映を分離し、再送で重複しない。
- 実行結果はテストログ、スクリーンショット、またはレスポンス確認として保存する。
