# バリデーション一覧

## 1. 目的

入力ミスを保存前に検知し、利用者が修正できる日本語メッセージで返すための検証規則をまとめる。APIの検証が最終防衛線であり、画面の入力制限だけには依存しない。

## 2. 成績入力・評価計算

| 対象 | 検証規則 | エラーコード／メッセージ | 根拠 |
|---|---|---|---|
| 出席率 | null または0〜100の整数 | `INVALID_ATTENDANCE_RATE`／「出席率は0〜100の整数で入力してください。」 | `apps/api/src/grade/calculation.ts:21-31` |
| 平常点 | null または1〜10の整数 | `INVALID_ATTITUDE` | 同上 |
| 課題点 | null または1〜10の整数 | `INVALID_ASSIGNMENT` | 同上 |
| 成績レコード | `studentId` が空でない文字列 | `INVALID_STUDENT_ID` | `apps/api/src/grade/routes.ts:25-33` |
| 成績配列 | JSONの `grades` が配列 | `INVALID_GRADES` | `apps/api/src/grade/routes.ts:39-42` |
| 評価比重 | 各項目0〜100の整数 | `INVALID_*_WEIGHT` | `apps/api/src/grade/calculation.ts:33-36` |
| 評価比重合計 | 出席率・平常点・課題点の合計が100 | `INVALID_WEIGHT_TOTAL`／「評価比重の合計を100にしてください。」 | `apps/api/src/grade/calculation.ts:37-40` |
| 学期 | 1または2 | `INVALID_TERM`／「学期は1または2を指定してください。」 | `apps/api/src/grade/routes.ts:9-12` |
| 年度 | 4桁の数字 | `INVALID_ACADEMIC_YEAR` | `apps/api/src/grade/routes.ts:14-17` |
| 成績状態 | 入力未完了なら最終点・評価を保存しない | nullのまま保持 | `apps/api/src/grade/calculation.ts:52-66` |

評価は、出席率をそのまま、平常点・課題点を10倍して比重を掛け、100分率の整数分子として計算する。S/A/B/C/Fの境界は90/80/70/60点相当で、丸めずに判定する。

## 5. 理由・JSON・失敗時の表示

- 成績修正・再試験登録の理由は空白だけを拒否する（`CORRECTION_REASON_REQUIRED`）。
- 確定済み成績の再開理由は必須（`REOPEN_REASON_REQUIRED`）。
- 在籍状態変更の適用年度と理由は必須で、現在年度以外は409（`STATUS_EFFECTIVE_YEAR_NOT_CURRENT`）。
- 壊れたJSONは400（`INVALID_JSON`／「JSONの形式が正しくありません。」）。
- 未知のサーバーエラーは内部値を返さず、画面には「処理に失敗しました。」を表示する。

根拠：`apps/api/src/grade/routes.ts:53-62, 99-125`、`apps/api/src/admin/routes.ts:25-33, 65-68`、`apps/api/src/admin/route-errors.ts`。

## 6. テスト確認と残る境界

検証規則はAPIユニット・統合テスト、Web状態テスト、E2Eシナリオで確認する。実際の利用者が入力する全IME・異体字・メール配送結果、および本番環境のCSVファイル文字コードは、ローカルテストだけでは保証しない。
